# アプリ内の新着リスト

案件一覧の上部に、未読の更新内容を英語で表示します。`Close` を押すまでリロードや再起動後も表示し、閉じると今回の未読分すべてを既読にします。一度に表示するのは新しい5回分までで、それ以前の未読分は件数を案内します。案件画面のツールバーには追加しません。

新しいブラウザーの初回（既読キーなし）は最新1件を表示します。Closeまで自動で既読を書き込まず、reloadや別タブでも最新1件を表示します。この初回表示には過去分の残数を出しません。既読情報はブラウザーごとに保持するため、別端末やブラウザーデータ削除後は再び初回扱いになります。ストレージを読めない場合は非表示のまま案件操作を続けられます。閉じた情報を書き込めない場合は、その場では閉じますが再読み込みで再表示されます。

旧版が初回訪問時に自動記録したIDと、利用者がCloseしたIDは区別できません。既に同じIDが記録されている利用者へ同じ内容を強制再掲するためのキー消去・改名は行いません。次リリースでは新しいIDを追加してください。

## 履歴の保守

- `app/data/user-changelog.json` の `entries` に新しい順で追加します。独立JSONを静的importするため、履歴取得用の通信はありません。
- `id` は日付と連番による一意で変更しない識別子です（例: `2026-09-17-1`）。アプリ版番号ではありません。既存IDを再利用せず、既存履歴を残します。未確定の版番号やSHAを推測して書きません。
- `date` は案内する更新の日付、`title` と `items` は平易な英語で利用者に関係する変更を記載します。初回に表示するのは、この並びの最新1件です。
- 利用者向けの公開可能な更新内容リストを根拠にします。私有の共有履歴を転記しません。顧客名、案件名/識別子、内部パス、DB識別子、認証情報を含めません。
- リリース準備では、更新内容との一致、ID重複なし、新しい順、英文、秘匿情報なし、静的buildへの同梱を確認します。正式な公開前検証と既存の秘匿監査は別途必要です。

## 既読情報と異常時

専用キー `cfs-user-changelog-seen-v1` に `{ "lastSeenId": "..." }` を保存します。案件保存のキー、schema、更新APIは使用しません。

| 状態 | 動作 |
| --- | --- |
| キーなし | 最新1件を表示。Closeまで既読を書かない。過去分の残数表示なし |
| 空文字、不正JSON、型不正、空ID | 表示せず最新IDを記録し、不正状態を初期化 |
| 最新IDと一致 | 表示なし。旧版の自動記録も同じ既読状態として扱う |
| 有効だが現在の履歴にないID | 保持中の全履歴を未読扱い（最大5回分） |
| 履歴が空 | 表示なし。既読キーは変更しない |
| storage取得・読取り不可 | 新着は表示せず、案件操作を継続 |
| 書込み不可 | キーなしなら最新1件を表示。Closeで現在の表示は消えるが、再読込み/一覧再訪時は以前の既読状態に従う（キーなしのままなら最新1件を再表示） |

## 記述言語(2026-09-24、版 26.9.2 から)

- 各 entry の `title` と `items` は **英語 ／ 日本語 の併記**にする(区切りは全角スラッシュ「 ／ 」、英語→日本語の順)。UI 文言は英語のまま、利用者向けの説明は日本語で読めるようにするため(ユーザー指示 2026-09-24)。
- 過去の entry(2026-09-24-1 以前)は英語のみのまま据え置く。
