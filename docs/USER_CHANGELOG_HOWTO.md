# アプリ内の新着リスト

案件一覧の上部に、未読の更新内容を英語で表示します。`Close` を押すまでリロードや再起動後も表示し、閉じると今回の未読分すべてを既読にします。一度に表示するのは新しい5回分までで、それ以前の未読分は件数を案内します。案件画面のツールバーには追加しません。

新しいブラウザーの初回は過去分を表示せず、現在の履歴を基準として記録します。既読情報はブラウザーごとに保持するため、別端末やブラウザーデータ削除後は再び初回扱いになります。ストレージを利用できない場合も案件操作は続けられます。閉じた情報を保存できない場合、再読み込みで再表示されることがあります。

## 履歴の保守

- `app/data/user-changelog.json` の `entries` に新しい順で追加します。独立JSONを静的importするため、履歴取得用の通信はありません。
- `id` は日付と連番による一意で変更しない識別子です（例: `2026-09-17-1`）。アプリ版番号ではありません。既存IDを再利用せず、既存履歴を残します。未確定の版番号やSHAを推測して書きません。
- `date` は案内する更新の日付、`title` と `items` は平易な英語で利用者に関係する変更を記載します。現在の初期1件は2026-09-17に公開された更新の5点です。
- 利用者向けの公開可能な更新内容リストを根拠にします。私有の共有履歴を転記しません。顧客名、案件名/識別子、内部パス、DB識別子、認証情報を含めません。
- リリース準備では、更新内容との一致、ID重複なし、新しい順、英文、秘匿情報なし、静的buildへの同梱を確認します。正式な公開前検証と既存の秘匿監査は別途必要です。

## 既読情報と異常時

専用キー `cfs-user-changelog-seen-v1` に `{ "lastSeenId": "..." }` を保存します。案件保存のキー、schema、更新APIは使用しません。

| 状態 | 動作 |
| --- | --- |
| キーなし、空文字、不正JSON、型不正、空ID | 初回扱い。表示せず最新IDを記録 |
| 有効だが現在の履歴にないID | 保持中の全履歴を未読扱い（最大5回分） |
| 履歴が空 | 表示なし。既読キーは変更しない |
| storage取得・読取り不可 | 新着は表示せず、案件操作を継続 |
| 書込み不可 | 初回は非表示。未読を閉じると現在の表示は消えるが、再読込み/一覧再訪時は以前の既読状態に従う |
