# CFS 更新診断ツール

配布された診断tools ZIPを、CFSのインストール先とは別のフォルダーへ展開してください。`COLLECT_CFS_UPDATE_DIAGNOSTICS.cmd`を開き、調べるCFSフォルダーと、診断ZIPの保存先を選びます。保存先はCFSフォルダーの外にある新しいファイルを指定します。

対話操作では、成功時に保存先を示す英語の確認画面が残ります。失敗時は英語の案内に従い、DownloadsなどCFS外のローカルフォルダーに新しいZIP名を指定してください。リンク・リダイレクトされたフォルダーは使用できません。選択をキャンセルすると採取せず終了します。

アプリが起動中でも停止中でも採取できます。採取は更新・停止・再起動・設定変更を実行しません。既存26.10.2も対象です。旧版にはCPU/IO・heartbeat・稼働時計の記録がないため、それらを推測せず「旧形式では取得不可」と記録します。旧ログの時刻は最後の実活動時刻ではありません。

ZIPに入るのは許可された工程・時刻・終了値などの構造化情報です。生ログの自由文、案件データ、認証値、環境設定、API応答、command lineは含めません。情報を安全に抽出できない場合は省略理由を記録します。処理中の取得は複数ファイルを順番に読むため、完全に同時刻のsnapshotではありません。

新しい更新workerでは独立した英語の監視画面が開きます。workerの応答と実OS活動は別表示です。30秒以上応答がない場合は観測が古いこと、5分以上の場合は未応答エラーを表示します。これは更新停止の確認ではありません。再更新やプロセス停止を重ねず、Export diagnosticsで診断を保存してください。画面を閉じても更新処理は停止しません。

監視画面は完了・失敗後も閉じるまで残ります。閉じた後に診断を採取する場合は、上記の独立した診断ツールを使用してください。更新を再実行して監視画面を開き直さないでください。コマンドの後始末が未確認の場合は保護を維持するため、失敗表示でも再更新できません。

コマンドの稼働時間上限はGit3分、npm導入合計20分、build20分です。worker全体60分は安全な処理境界で確認します。同期ファイル処理やCIMを期限で強制停止する機能ではなく、全工程の厳密な時間上限を保証するものではありません。観測の空白やOS休止と処理停止は区別して扱います。

ブラウザーの時間表示は残る工程の参考値で、実測に基づく完了時刻予測ではありません。観測が古い・取得できない場合、後始末を確認中の場合、完了・失敗時には数値の参考時間を表示しません。
