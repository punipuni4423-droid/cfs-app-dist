起動に必要な条件とファイル

分類必要なもの説明
OSWindows PCLAUNCH_CFS_APP.cmd、START_CFS_APP_CONSOLE.bat、ショートカット作成スクリプトはWindows向けです。
ネットワークDatabase接続とApp Update時のインターネット接続最新版の配布Zipはビルド済みruntimeとNode.js runtimeを同梱します。Git管理ZipではPortableGitも同梱します。Database版ではSupabaseとMicrosoftログインへの接続が必要です。
認証Microsoftアカウント共有データベース版では、管理者が登録したメールアドレスでログインします。プロジェクトが表示されない場合はログイン状態と権限を確認します。
実行ファイルLAUNCH_CFS_APP.cmd通常起動用です。ダブルクリックすると起動準備を行い、ブラウザでCFSを開きます。
補助起動START_CFS_APP_CONSOLE.batログ確認や手動起動に使います。通常起動で開かない場合の診断用です。
ショートカットCREATE_DESKTOP_SHORTCUT.vbsデスクトップとスタートメニューにCFS Appショートカットを作成します。作成後のメッセージで参照先フォルダを確認できます。
Database設定cfs-public-supabase.envDatabase版に必要な公開設定です。Service Role Keyやクライアントシークレットは入れません。
同梱必須runtime、.cfs-runtime、app、public、scriptsビルド済みruntime、Node.js runtime、アプリ本体、起動補助スクリプトです。Git管理Zipでは .cfs-runtime\git も含みます。
同梱しないものdata、.env.local、生の .next、ルートの node_modules配布Zipではユーザーデータ、秘密情報、開発用ビルド成果物は含めません。通常Zipは .git を含めず、Git管理ZipのみApp Update用に含めます。
OneDriveやネットワーク共有フォルダ上で直接起動すると、同期やファイルロックで不安定になることがあります。まずローカルフォルダへ解凍して起動してください。

起動手順

1. Zipを解凍
任意のローカルフォルダへ展開します。フォルダ名に日本語やスペースがあっても動作しますが、深すぎるパスは避けます。
2. 起動
LAUNCH_CFS_APP.cmd をダブルクリックします。通常は利用者PCでnpm installやNext buildを行いません。
3. ブラウザ表示
準備が完了すると http://localhost:3014 などのローカルURLが開きます。同じポートに別フォルダの古いCFSがいる場合は、自動で空きポートへ退避します。
4. ログイン
Database版ではMicrosoftログインを行います。ログイン後に権限があるプロジェクトが表示されます。
5. ショートカット
必要に応じて CREATE_DESKTOP_SHORTCUT.vbs を実行します。新しいZipへ入れ替えた時は、古いショートカットを削除して新しい解凍フォルダから作り直します。

起動状況は artifacts\startup\latest-status.txt と同フォルダの最新ログで確認できます。

InspectionMode

No名称機能保存動作
1InspectionModeボタン点検モードの開始/終了を行います。終了時に複数RoomTypeで編集がある場合は対象を一覧で選び、まとめて保存できます。
2Linked / Unlink、Select / Copy / Paste / Clear / RevertArea Scene連動を維持するか、個別上書きにするかを選び、範囲編集を行います。LinkedはArea Sceneへ、Unlinkは直接値/上書きへ反映します。
3CFSセル選択セルまたは範囲を選んで値を編集します。編集済みセルはInspectionのドラフトとして保持されます。
40% / 100% / -10 / -1 / +1 / +10 / Raise / Lower / Uneffected調光値や標準動作を素早く入力します。0%と100%は即座に値入力欄へ反映されます。
複数RoomTypeでInspection編集した場合は、終了時に編集されたRoomTypeを一覧表示し、チェックしたRoomTypeだけRevision保存する運用が推奨です。現在選択中のRoomTypeだけを無言で保存する形にはしません。

トラブル対応

症状確認する場所対応
起動しない、96%付近で止まるartifacts\startup\latest-status.txt、最新の start-*.log、server-*.logポート使用中、ビルド失敗、依存関係取得失敗を確認します。必要に応じて別ポートで起動します。
新しいZipを入れたのに画面が古いデスクトップ/スタートメニューの CFS App ショートカット、/api/app-update/status の appDir古いショートカットは以前の解凍フォルダを指し続けます。古いショートカットを削除し、新しい解凍フォルダの CREATE_DESKTOP_SHORTCUT.vbs で作り直します。
ログイン後にプロジェクトがないMicrosoftログイン状態、管理者登録、Database接続ログインし直し、管理者にメール登録を確認します。ブラウザの認証トークンが古い場合は再ログインします。
Failed to save locallyと出るブラウザストレージ容量Database版ではDB保存が主ですが、ブラウザバックアップの容量が不足している可能性があります。不要プロジェクトや古いRevisionを整理します。
Git was not foundが出る.cfs-runtime\git、/api/app-update/status の gitPathGit管理ZipではPortableGitを同梱します。古いZipや古いショートカットを使っていないか確認します。通常ZipはGit更新対象外です。
Update Blockedが出るGit管理された既存アプリの差分ローカルの追跡ファイル変更をコミットまたは破棄してから更新します。配布Zip版では通常Git更新の対象ではありません。
CFSに行が出ないCircuit、Device AssignCFSはCircuitとDevice Assignの連携からBase行を作ります。Circuit # / InputやDetailが不足していないか確認します。
CCOのArea/Detailが意図と違うCircuitタブのDry Contact、Device AssignのCCO行Dry ContactでArea、Circuit、Detailを登録し、Device Assignではリストから選択します。Detail空欄時はCFS上でCircuitを表示します。
ハイライトが広く出るHighlight Updates、Revision履歴差分表示はセル単位が基本です。行追加時のみ行単位で強調されます。最新Revisionを保存して比較元を整えます。

この取説のスクショは、実データを含まないManual Demo Projectで取得しています。画面構成とボタン配置は2026年8月7日時点のアプリに基づきます。
