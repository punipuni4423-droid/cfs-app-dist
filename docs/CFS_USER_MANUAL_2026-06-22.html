CFS App ユーザーマニュアル

一般配布版 / 更新日: 2026-06-23

このマニュアルは、CFSアプリをローカル環境で共有・運用するための一般化された説明書です。特定プロジェクト名には依存しません。

1. アプリの目的

CFS Appは、照明制御、デバイス割当、シーン、スイッチ、PIR/QSM、Backlight、HVACなどの情報を整理し、CFSとして確認・出力するためのローカルWebアプリです。

作業データはアプリフォルダ内の data/projects.json と data/trash/trash.json に保存されます。

2. 起動方法

  1. ZIPを任意のフォルダへ展開します。
  2. Node.js LTSをインストールします。
  3. START_CFS_APP.bat をダブルクリックします。
  4. 初回のみ依存関係のインストールが実行されます。
  5. ブラウザで http://localhost:3000 を開きます。
既に別のアプリが3000番ポートを使用している場合、起動ログに表示される別ポートのURLを開いてください。

3. 基本ワークフロー

  1. Projectを作成または選択します。
  2. Locations / Areasで部屋・エリアを登録します。
  3. Fixturesで照明器具情報を登録します。
  4. Circuitで回路、調光方式、Detail、Areaを登録します。
  5. Device Assignでデバイス、ゾーン、CCI/CCO、DALIアドレスを割り当てます。
  6. Scene / Area Scene / Switch / Command / Backlightを設定します。
  7. CFSタブで最終的な並び、Detail、Area Address、Programming Nameを確認します。検査時に値を調整する場合はInspectionModeでドラフトを作り、終了時の確認ダイアログで反映します。
  8. 必要に応じてExcelやJSONを出力します。

5. CFSタブの確認ポイント

  • Area Highlightを使い、同じAreaの行まとまりを確認します。
  • Area Addressが重複していないことを確認します。
  • Programming Nameが標準形式になっていることを確認します。
  • DALIの個別灯にSwitch/Scene値を設定している場合、CFSの同じDetail行に値が出ていることを確認します。
  • Base Columns / Function Columnsは、列見出し上の小ボタンまたは列メニューで表示/非表示を切り替えます。
  • Circuit / Device Assign / Switchの表は大きめのリサイズ可能な作業領域で表示し、表内スクロール時も見出し行を固定して確認します。
  • InspectionModeでは、CFS上で%やOn/Off値をドラフト編集できます。Linkedは参照元のArea Scene値を調整し、Unlinkはセル単位のOverrideとして調整します。セル編集オーバーレイのOKは入力済みのドラフト値を保持して閉じ、Resetはそのセルを元の値へ戻して閉じます。InspectionMode開始前の値へ戻す場合は、InspectionModeツールバーのRevertでセッション全体を取り消します。InspectionMode終了時の確認ダイアログで、新Revisionとして保存するか、現在のRevisionのまま完了するかを選びます。Inspection MarkはHighlightsのInspection Marksで表示/非表示を切り替えられ、通常のSave as New Revisionでは一度リセットされます。
  • Linked Valuesの塗りつぶしは通常非表示です。SettingsのDisplayでAdmin ModeをONにし、CFS Linked Values fillをONにした場合だけ、Scene / Switch / Commandなどと連動しているCFSの機能セルが薄いシアンで表示されます。
  • 通常確認やExcel出力前は、InspectionModeをOFFにして表示状態を確認します。
  • Link Mapは通常非表示です。SettingsのDisplayでAdmin ModeとCFS Link MapをONにした場合だけ、CFSタブにLink Mapボタンが表示されます。Overviewは固定レーン型のDependency mapで、Source Data、Scene Values、System Logic、CFS Output、Inspection Finishの流れを確認します。各レーンの代表ノードや連動ルートカードをクリックすると、Current Links、All Rules、Warningsで現状リンク、期待ルール、警告、スナップショット署名を確認できます。赤いセル強調は修正が必要なErrorを中心に表示し、確認が必要なWarningはタブ表示と診断リストで確認します。
  • BacklightのLink Map警告では、参照先グループが存在しない場合と、グループは存在するがBacklight対象ではない場合を分けて表示します。CFS Backlight Logicに出す場合は、対象側をBy SceneまたはBaseに設定します。By Sceneは対象指定用の状態であり、CFSには値として表示せず、BaseやMaster Onなど実際のBacklight Scene名だけを表示します。Switch番号、名称、CCI割当、Functionなどが空の未入力行はBacklight警告対象にしません。
  • WarningsにStale HVAC targetが出た場合は、旧HVAC IDをArea Sceneが参照している可能性があります。復旧候補が一意に判定できる場合はRepair Stale HVACで現行HVAC targetへ置換し、復旧直後のRepaired Linksハイライトで該当セルを確認します。
  • DALIはGroup/AddressまたはLine/Group/Addressの並びを確認します。
  • CCI/CCOは照明制御と非照明制御でDetailの出方が異なるため、CFS側で確認します。
  • HVACとBacklight Logicは照明系の並びとは別扱いとして確認します。

6. データ保存とバックアップ

プロジェクトデータは data フォルダ内に保存されます。アプリを更新するときは、このフォルダを削除または上書きしないでください。

  • 通常バックアップ: data フォルダをコピーします。
  • 共有前バックアップ: Project画面のExport、またはJSONバックアップを保存します。
  • 復旧: バックアップした data/projects.json を戻します。

7. 共有とアップデート

フルZIP

初回配布用です。アプリ本体と現在の data フォルダを含みます。別のPCへ同じ状態を渡す場合に使います。

アップデートパッチZIP

更新用です。アプリ本体だけを含み、data フォルダは含みません。既存プロジェクトを残したまま更新する場合に使います。

既存環境を更新するときは、フルZIPで上書きせず、データなしのアップデートパッチZIPを使用してください。
