# CFSを空のフォルダーへ再インストールする

旧版Zipに戻す場合は、**空の新フォルダーへ展開**してください。既存フォルダーへ上書きすると、Zipに含まれない新しいビルドや更新用ファイルが残り、元の版に戻らないことがあります。

1. 旧CFSの保存を終えて閉じます。旧CFSに対応する`node.exe`を終了するか、PCを再起動します。他のアプリのNodeプロセスは終了しないでください。
2. Zipを空の新フォルダーへ展開し、その中の`CLEAN_REINSTALL_CFS_APP.cmd`を実行します。
3. helperは既存CFSショートカットから旧フォルダーを特定し、そのフォルダーのサーバー・接続リダイレクトhelper・既知のランチャーが停止したことを確認してから、新しいショートカットと起動へ進みます。旧フォルダーの`_old_日時`への変更は任意です。dataの自動移動・削除は行いません。

初回導入やショートカットが新フォルダーを向く場合は、対象ポートが空き、別フォルダーのCFSサーバー/helperが見当たらなければ停止処理なしで進みます。既定の対象ポートは3014と接続リダイレクト用3000です（環境変数`PORT` / `CFS_AUTH_REDIRECT_PORT`指定時はその値）。ショートカットがなく旧アプリが残る場合や、`-NoShortcut`で旧アプリを入れ替える場合は、旧フォルダーを明示します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\clean-reinstall-cfs-app.ps1" -AppRoot "D:\Apps\CFS-new" -OldAppRoot "D:\Apps\CFS-old"
```

旧rootが不明で対象ポート使用中・別サーバー/helperがある場合、reparse/junctionを含む場合、停止対象の起動時刻を照合できない場合、停止できない場合、旧待受ポートが残る場合は中断し、新起動を行いません。起動引数が読めない無関係プロセスは無視しますが、対象ポートの所有者を確認できない場合は拒否します。対象を確認して旧アプリを終了し、再実行してください。別ポートへ逃げたことを再インストール成功とは扱いません。

`-SkipProcessStop`は、旧プロセスが既に停止済みのときだけ後続へ進みます。新フォルダー自身・旧新の親子関係・開発確認フォルダー`cfs-app-verify`・`.update-qa`は停止/rename対象にできません。相対パスや複雑なshell式で起動した旧アプリは自動停止対象として確定できないため、手動終了が必要です。

ログは新フォルダーの`artifacts\startup\clean-reinstall-*.log`に残ります。設定やdataの引継ぎは、旧フォルダーのバックアップを確保し、利用する版の手順に従って行ってください。
