# 読込時の修復・除外と保存の確認

データの読込時に不正な要素が見つかった場合、正常な要素を残して読み込みます。画面上部の通知には修復・除外の件数を表示し、「修復・除外の詳細」で対象を確認できます。通知中はブラウザの自動ドラフト保存を停止し、元の保存データを自動で上書きしません。

内容を確認し、通常の保存ボタンを押してください。修復・除外を含む保存の確認が表示されます。キャンセルすると保存せず、編集画面と元データを保持します。続行すると保存を試みます。

サーバーの保存データより件数が減る場合には、対象と件数を示す追加確認があります。意図した削除であることを確認して保存してください。確認の間に対象データが変わった場合は、再確認が必要です。別の利用者が保存した場合の競合チェックは引き続き有効です。

正常な旧形式データの読込、意図した空サーバーの優先、Backlight の既存の正規化は維持します。データが正しくない場合に、正常な Switch・Scene・部屋タイプ等まで一括削除する処理を避けるための保護です。

Scene が全件不正で除外された場合は、その読込では空の状態を表示し、確認が終わるまで既定シーンの自動補完も停止します。もともと正常な空の Scene データを読み込む場合は、従来の既定生成を維持します。この区別は確認中のブラウザ状態で管理し、Project JSON に新しい保存項目を追加しません。

API 利用者向け: `GET /api/projects` の `migrationReport` に診断を追加しました。縮小を含む POST は `409 / MIGRATION_CONFIRMATION_REQUIRED` と診断・`migrationConfirmation` を返します。利用者に内容を提示して確認した後、同じ本文へ返された `migrationConfirmation` を追加して再送します。通常保存の本文、保存形式 v14、Project/Share JSON、XC/LD エクスポートの形式は変更しません。
